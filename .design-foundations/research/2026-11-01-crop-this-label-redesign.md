# Design Research Brief: Crop This Label Full Redesign & Logo Exploration

**Date:** 2026-11-01
**Project:** Crop This Label (`crop-this-label`)
**Stage:** Stage 1 (`research`) — Confirmed Discovery Brief

---

## 1. Problem & Primary Audience

### The Problem
**Crop This Label** is a fast, 100% client-side AI utility (`onnxruntime-web` + `pdf.js` + `label-model.onnx`) that automatically detects, crops, auto-orients, and formats 4×6 thermal shipping labels (`1200×1800` px) from full-page carrier PDFs and images.

Currently, its entire UI was generated by default LLM heuristics (`bg-slate-50`, `#4f46e5` indigo-600 primary buttons, generic Lucide `Scissors` icon inside an indigo rounded square, symmetrical rounded-2xl cards, emerald-50 and amber-50 pill banners, and an `animate-pulse` "Match #1 (Wrong? Click me)" pill). It looks like a generic SaaS boilerplate rather than a high-craft physical shipping/label utility, and it lacks an authentic brand mark.

### Primary Audience
- **E-commerce & marketplace sellers** (Poshmark, eBay, Mercari, Depop, Etsy, PirateShip, Shopify) and **small warehouse / home-office shippers** printing onto 4×6 thermal label printers (Rollo, Zebra, Munbyn, Dymo).
- **Usage context**: Utility-first, high-frequency, task-driven. Users arrive with a PDF or screenshot in hand (or clipboard) and want to get a clean 4×6 label to their printer or downloads folder in under 5 seconds—with total confidence that the label is accurately cropped, properly oriented, and processed locally without uploading customer addresses to a third-party server.

---

## 2. Target Surface & Platform

- **Surface**: Desktop-first responsive web application (React 19 + Vite + Tailwind CSS), with clean mobile/tablet responsiveness for sellers cropping labels on their phone/tablet before AirPrinting or saving.
- **Register**: **Product / Workbench Utility Register** — zero marketing bloat, unmistakable primary focal point (the 4×6 label stage and upload dropzone), tactile precision around physical print dimensions (`4" × 6"` / `1200 × 1800 px`), and expressive moments at **Detection Scan**, **4×6 Label Lock-In**, and **Logo/Brand Identity**.

---

## 3. Key User Flows & Primary Actions

### Flow 1: Instant Label Intake (Empty / Ready State)
- **Primary Action**: Drop a PDF/image anywhere on the window, click the intake zone, or press `Ctrl+V` / `Cmd+V` to paste an image directly from the clipboard.
- **Trust & Privacy Signal**: Clear, non-cliché local-execution indicator showing that the ONNX vision model + PDF renderer run 100% in-browser (zero server uploads, customer PII never leaves the device).
- **Model/PDF Readiness**: Clear status indicator while `label-model.onnx` and `pdf.js` initialize (`loading` → `ready`).

### Flow 2: Multi-Page AI Scanning (`processing` State)
- **Feedback**: Page-by-page scanning progress (`Scanning page X of Y...`) with a deliberate, technical visual treatment on the source preview canvas.

### Flow 3: 4×6 Label Inspection, Candidate Selection & Orientation (`success` State)
- **Primary Focal Point**: The cropped **4×6 thermal label stage** (`2:3` aspect ratio, `1200×1800 px`) presented with physical print-scale cues (4" × 6" dimension callouts, registration marks, or thermal stock framing).
- **Visual Candidate Switcher (UX Upgrade)**: When the ONNX model detects multiple label candidates across pages (or multiple bounding boxes), replace the blind `Match #1 (Wrong? Click me)` pulsing pill with a **visual candidate selector / thumbnail strip** showing candidate number, confidence %, and source page so users can switch detections with certainty.
- **Orientation & Source Controls**:
  - **Rotate 90° CW** and **Flip 180°** controls with immediate canvas update.
  - Compact **Source Document Preview** showing where the crop was extracted from (plus quick "Upload New / Reset" trigger).
- **Primary Output Actions**:
  - **Print 4×6 Label** (opens dedicated `@page { size: 4in 6in; margin: 0 }` print window) and **Download PNG** (`label_<timestamp>.png`) as co-equal or clearly ranked primary completion actions.

### Flow 4: No-Detection / Error Recovery (`error` State)
- Clear diagnostic message when no shipping label bounding box exceeds the confidence threshold, with one-click retry/upload another file.

### Flow 5: Logo & Brand Mark Exploration (Dedicated Deliverable)
- A dedicated **Logo & Brand Mark Mockup Sheet** (`mocks/logo-options.html`) presenting **6 distinct custom SVG logo + favicon concepts** across three structural families:
  1. **Geometric & Technical** (crop-corner registration brackets + 4×6 label silhouette; barcode/perforation geometry)
  2. **Tactile & Literal** (peeled thermal label corner / backing sheet; rotary blade / utility cutter + parcel tag)
  3. **Typographic & Stencil** (`CTL` shipping stencil/stamp monogram; wordmark with a physically sliced/cropped letterform)
- Each logo option rendered in context: Navbar lockup, `32×32` & `16×16` favicon scale, light/dark surface, and 1-bit monochrome thermal-stamp test.

## 4. Taste Signals & Multi-Direction Mock Strategy

### User Taste Signals Captured
1. **Visual Direction — "Mock Them All So I Can Pick One"**:
   - Rather than locking a single aesthetic direction blind in text, the user explicitly requested **visual mockups of all 4 proposed directions** so they can compare them side-by-side and pick the winner before the React build:
     - **Direction A — Tactile Industrial & Postal Utility**: Physical shipping manifest vibe, crisp hairline grids, monospace 4×6 spec readouts, warm paper/cardstock neutrals + one high-visibility accent (e.g., safety orange, signal yellow, or postal cobalt).
     - **Direction B — Precision Studio / Cutting-Mat Workbench**: High-craft dark or crisp light inspection stage (like Linear / Figma), technical crop registration marks, dot/grid cutting-mat canvas, ultra-clean tool dock.
     - **Direction C — Warm Seller / Kraft-Paper Craft**: Approachable, tactile, bold ink borders and warm cardboard/kraft tones tailored for Poshmark, eBay, Etsy, and PirateShip sellers.
     - **Direction D — Stark Swiss / Thermal Monochrome**: Pure black-and-white thermal-printer contrast, bold grotesque typography, exposed hairlines, and a single surgical accent color.
2. **Logo Exploration**:
   - Wants a spread of **5–6 distinct SVG logo concepts** across Geometric/Technical, Tactile/Literal, and Typographic/Stencil styles mocked up for comparison.
3. **UX Scope**:
   - Confirmed **Single-screen workbench + small UX upgrades** (visual candidate switcher replacing the blind pulsing button, window-wide drag-and-drop + `Ctrl+V` clipboard paste, and true 4×6 print-scale preview).

### Suggested `dealer.mjs` Strategy for Stage 2 & Stage 3
- Run `dealer.mjs --project "crop-this-label" --date 2026-11-01 --candidates 5` (no single-family pin, allowing the dealer to spread across aesthetic families, layout disciplines, and seed hues) and map the dealt candidates + `palette.mjs` token sets to the 4+ visual directions so Stage 3 (`mocks/`) lets the user visually compare all directions AND the 6 logo options before Stage 4 React implementation.

---

## 5. Anti-Goals / Explicit Exclusions

- **No generic AI/SaaS tells**: Ban `#4f46e5` indigo-600 + `slate-50` default Tailwind boilerplate, stock Lucide scissors-in-rounded-square brand mark, glowing purple/cyan gradients, uniform 3-column marketing feature cards, and `animate-pulse` pills.
- **No backend or cloud dependencies**: Everything must remain 100% client-side (`onnxruntime-web` WASM + `pdf.js`).
- **No bloated multi-page marketing funnel**: Keep the app a fast, immediate single-screen workbench where the tool IS the landing experience.

---

## 6. Open Risks / Assumptions

- **ONNX & PDF.js Worker Preservation**: The existing Web Worker inference pipeline (`WORKER_CODE`, `label-model.onnx`, `pdf.js` scale 4.0 rendering, and `1200×1800` crop/auto-landscape rotation math) works reliably and must be preserved intact during the Stage 4 React UI rebuild.
- **Multi-Direction Mock Gate (Stage 3)**: In Stage 3, we will render both the **Logo Options Mockup (`mocks/logo-options.html`)** and the **Multi-Direction Workbench Mockup (`mocks/workbench-directions.html`)** so the user can test-drive all 4 aesthetic directions and 6 logo marks in one interactive sign-off gate before we code the production React components.
